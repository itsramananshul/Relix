Capabilities

Every capability advertised by every peer in the cached topology. Click any row to see the owning peer + freshness. Filter by category (top chips) or by name (text input).

All advertised capabilities

loading…

Sourced from /v1/topology — every peer's manifest methods[] aggregated. Honest: capabilities that haven't been called yet still appear here (this is the catalog, not the live invocation history). A capability returning BackendNotConnected at invocation time (browser, MCP) still ships its descriptor; operators see what's wired vs gated by looking at the source peer's node_type + the capability's name.

Policy "What If?"

Pure read — no method is invoked. The simulation inherits the caller's identity (subject_id, org_id, role, clearance) but swaps groups for the supplied list. Used to validate policy changes before deploying.

MCP Registry

Model Context Protocol servers registered on the tool node. Sourced from /v1/mcp/servers + /v1/mcp/tools (PH-BRIDGE-MCP) — bridge proxies the live registry via the existing mesh client. Honest: per D-009 the stdio runtime is not yet wired, so invoke returns RuntimeNotConnected; the registry contents shown here are operator-declared in [[tool.mcp.servers]].

Recent invocations

loading…

Bounded ring of every dispatched POST /v1/mcp/invoke call (capacity 256, newest first). Sourced from /v1/mcp/audit (PH-BRIDGE-MCP-AUDIT). Resets on bridge restart. Args are not stored — only the argument byte count, the outcome, and (on failure) the responder envelope kind.

Filesystem Audit

Per-jail mutation ring on the tool node — every successful write / append / patch / fuzzy_replace pushes one row. Sourced from /v1/fs/audit which proxies tool.fs.audit_recent via the existing mesh client. Bounded (256, newest first); resets on tool-node restart. Independent of the dispatch-level audit log.

Recent mutations

loading…

Caller ids are abbreviated; hover for the full 32-byte fingerprint. The op filter is enforced by the responder — passing an unknown op yields HTTP 400.

Web host blocklist

loading…

Sourced from /v1/tool/blocklist which proxies tool.web.blocklist_summary. Operator-curated via [tool] blocked_hosts; refresh with a tool-node restart. Honest: not a live threat feed — see the URLhaus refresh recipe in the tool-node security doc.

Terminal Audit

Per-backend completion ring on the tool node — every finished tool.terminal.run / .spawn pushes one row when the child exits (or is killed by timeout / tool.terminal.cancel). Sourced from /v1/terminal/audit which proxies tool.terminal.audit_recent via the existing mesh client. Bounded; resets on tool-node restart. Args are not shipped — only the command, exit code, duration, and termination flags.

Recent completions

loading…

Killed rows (timeout / cancelled) show — in the exit column; the badge in the status column flags which one. Caller ids are abbreviated; hover for the full fingerprint.

Browser sessions

Currently-open tool.browser.* sessions on the tool node. Sourced from /v1/browser/sessions which proxies tool.browser.list_sessions via the existing mesh client. Read-only — open / navigate / close go through the libp2p dispatch path (or the AI flow that is driving the session). Reflects the operator-selected backend (none/headless_chrome/playwright/webdriver); the none scaffold shows unconnected status with no current URL.

Open sessions

loading…

Empty state means either no sessions have been opened OR the tool node is configured with [tool.browser] backend = "none" + nobody has called tool.browser.open_session yet. Use relix-cli capability invoke tool.browser.open_session (or an AI flow) to allocate one.

Dispatch metrics

Per-capability invocation counters + latency stats from the named peer's DispatchBridge. Sourced from /v1/dispatch/stats which proxies node.dispatch.stats. Lifetime counters — reset on peer restart. Latency tracks only Ok / Err outcomes (handler ran); policy-denied / unknown-method attempts don't contribute to latency.

AI Providers

Configure AI provider keys + default models. Keys are stored locally at bridge-secrets.toml (mode 0600, gitignored) and never sent back over HTTP. AI controller restart required for changes to take effect.

Local/dev only. These endpoints have no authentication. Put a reverse proxy with auth in front before exposing the bridge beyond loopback.

Telegram

Bot API token + delivery mode for the Telegram channel. The live HTTPS client wiring is pending — token is stored durably so when the live client ships, no operator re-entry is needed.

Local/dev only. No HTTP authentication on these endpoints. Production: put a reverse proxy with auth in front.

Setup

  1. Open Telegram and message @BotFather.
  2. Run /newbot and follow the prompts. Copy the API token (looks like 1234567:ABCDEF…).
  3. Paste it below and click Save. The token is stored at bridge-secrets.toml (mode 0600, gitignored). It is never echoed back via HTTP or written to logs.
  4. Restart the Telegram channel controller for the change to take effect.

Configuration

never echoed back; stored at mode 0600 in bridge-secrets.toml

Polling: the channel long-polls Telegram's getUpdates endpoint (shipped).
Webhook: persists URL + mode, but the live HTTPS receiver isn't wired yet — the channel will fall back to polling until that ships.

Required when mode=webhook. Must be https://. Telegram POSTs updates to this URL.
